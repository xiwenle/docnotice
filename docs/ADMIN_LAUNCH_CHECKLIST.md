# 管理员上线首周清单

> 第一周目标：账号、部门、分类可用；有首批资料；发出第一条通知；能看到谁还没看；完成灰度验证。

## 上线前（技术已就绪，确认业务侧）

- [ ] 生产服务器按 `DEPLOY.md` 部署完成，`/health` 200，`.env` 已改 SECRET_KEY 与初始管理员密码
- [ ] `.env` 中 `TRUSTED_HOSTS` 已包含员工实际访问域名/IP；上线后用浏览器实测一次资料保存/上传等写操作，确认未被 CSRF 403
- [ ] 手动点一次「立即备份」，确认备份列表出现记录（自动备份每周六 03:00 也会跑）
- [ ] 管理员账号就位（不要用初始 admin 日常办公，建个人账号并授予管理员）

## 第一周操作序列（顺序即员工第一眼体验）

### Day 1 — 建骨架
- [ ] 「部门管理」建好公司部门结构
- [ ] 「分类管理」建好资料分类树（最多 4 级，先少后多）
- [ ] 「用户管理」建**灰度部门**的员工账号（先只建一个部门）
- [ ] 「标签管理」按需建几个高频标签

### Day 2-3 — 放首批内容
- [ ] 上传**当前有效**的资料（只传员工真需要的，宁缺毋滥），逐一设置：
  - 分类、标签
  - 生效日期（今天）；有失效日期的务必填，没有就留空（=暂无失效日期）
  - 设置可见范围（全体 / 指定部门 / 指定人员），只让需要的人看到
- [ ] 用普通员工账号抽查：能搜到、能预览、可见即可下载；预览主文件，有附件默认下载原稿附件，无附件下载主文件

### Day 4-5 — 发第一条通知
- [ ] 发布一条通知（如《资料系统启用公告》），阅读对象=灰度部门；发布前确认弹窗会展示阅读对象人数与不可逆提示
- [ ] 观察被灰度员工：能否收到、能否打开查看；通知只记录「未查看 / 已查看」，没有额外确认开关

### Day 5-7 — 看数据、做灰度决策
- [ ] 「阅读统计」看三个观察点：
  | 观察点 | 健康线 / 做法 | 不达标先查 |
  |---|---|---|
  | 已查看率 | ≥ 80% | 员工是否知道系统上线了（宣传问题） |
  | 未查看名单 | 按实际应阅读人数核对 | 名单是否可筛选、可跟进 |
  | 搜索零结果 | 人工搜 10 个高频词 | 分类/命名是否符合员工语言 |
- [ ] 收集灰度部门反馈，修完问题后 → 建**全公司**账号、放开使用

## 日常节奏（第二周起）

- 资料更新：**上传新版**（旧版自动进回收站，勿手工覆盖）
- 每周六 03:00 系统自动备份；周一检查备份列表是否有「自动」记录
- 通知类：发布后在「阅读统计」跟进未查看名单与已查看率；系统只记录「未查看 / 已查看」
- 每季度：按 `DEPLOY.md` 做一次恢复演练（开发库实测已通过，照流程走即可）

## 红线提醒

- 分类 / 部门 / 标签 / 通知类型管理页删除前有确认弹窗；用户物理删除仍按锁定规则免二次确认，删除前想三秒
- 通知一旦有人查看，修改会留痕（修改人/时间/原因），改前想清楚
